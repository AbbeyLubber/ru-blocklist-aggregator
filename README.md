# ru-blocklist-aggregator

[🇬🇧 English](README.en.md) • 🇷🇺 Русский

Единый список заблокированных в России доменов, собранный из нескольких источников, плюс актуальный список IP-подсетей Telegram. Обновляется автоматически.

## О проекте

Несколько активно поддерживаемых проектов ведут собственные списки заблокированных в России доменов — каждый в своём формате и со своим циклом обновления. Этот репозиторий объединяет их в чистые списки без дублей — единый источник, на который можно настроить DNS-фильтр, прокси или роутер, вместо того чтобы следить за несколькими источниками по отдельности. Отдельно публикуется список IP-подсетей Telegram, включая сети, на которых физически лежат медиафайлы.

Репозиторий также ведёт `corp/` — отдельный набор списков доменов и IP-диапазонов крупных российских сервисов (Яндекс, VK, Сбер и другие) для маршрутизации их трафика как RU-домашнего. Это список доверия, а не блок-лист — подробности, методология и таблица файлов в [corp/README.md](corp/README.md).

## Файлы

| Файл / папка | Содержимое |
|---|---|
| `blocked/rkn-domain.txt` | Домены, по одному на строку, без wildcard-масок — максимальная совместимость (hosts-файлы, MikroTik `match-subdomain=yes`, exact-match блокировщики) |
| `blocked/rkn-with-wildcard.txt` | Те же домены, с префиксом `*.` там, где источник указывает на блокировку поддоменов — для AdGuard Home, sing-box и других инструментов с поддержкой wildcard |
| `blocked/ipv4.txt` | Заблокированные в России IPv4-подсети |
| `blocked/ipv6.txt` | Заблокированные в России IPv6-подсети (если для данного релиза есть актуальный источник — см. таблицу статуса) |
| `Telegram/telegram-ipv4.txt` | IPv4-подсети Telegram: собственные сети **плюс** CDN, на которых лежат медиа (см. оговорку под таблицей) |
| `Telegram/telegram-ipv6.txt` | IPv6-подсети Telegram: собственные сети **плюс** CDN, на которых лежат медиа (см. оговорку под таблицей) |
| [`corp/`](corp/README.md) | Домены и IP-диапазоны крупных российских сервисов (Яндекс, VK, Mail Group, Сбер, OZON, Wildberries, Avito, банки) — список доверия, не блок-лист. Полное описание папок и таблица файлов: [corp/README.md](corp/README.md) |


> ⚠️ **О списках Telegram.** Они содержат не только собственные сети Telegram, но и адреса CDN, на которых физически лежат медиафайлы — фото, видео, стикеры, файлы.
>
> Без этих сетей список покрывает сигнальную часть Telegram, но не отдачу контента. С ними покрытие полное — **однако те же сети обслуживают тысячи посторонних сайтов**, и правило, построенное на этом списке, затронет и их. Выбирайте осознанно: для маршрутизации «весь Telegram одним путём» это то, что нужно; для точечной блокировки — слишком широко.
>
> Диапазоны, принадлежащие российским сетям, из списков исключены.

## Статус списков

Таблица ниже обновляется автоматически при каждой публикации — вручную не редактировать. Статус файлов `corp/` — в [corp/README.md](corp/README.md), отдельной таблицей, чтобы не захламлять эту.

**Как читать эту таблицу.** Колонка «Обновлено» показывает, когда содержимое файла **фактически изменилось**, а не когда его в последний раз проверяли. Строка «Последняя проверка автоматикой» над таблицей — это момент последней сверки с источниками.

Расхождение между ними — норма, а не признак заброшенности. Если файл «обновлён» две недели назад, а проверка была сегодня, значит источник за это время не менялся и список по-прежнему актуален. Файлы переписываются только при реальном изменении данных: иначе дата сдвигалась бы при каждом запуске и перестала бы что-либо означать, а история коммитов заполнилась бы пустыми обновлениями.

## Как обновляются списки

Списки здесь живут по двум разным принципам — от этого зависит, чего от них ожидать.

**Зеркало — папка `Telegram/`.** Файлы пересобираются целиком, а не дополняются: диапазон, переставший быть актуальным, отсюда исчезает.

Списки покрывают собственные сети Telegram плюс CDN, с которых отдаются медиафайлы. Диапазоны, принадлежащие российским сетям, исключены.

**Накопитель — папки `blocked/` и `corp/`.** Записи только добавляются, автоматически ничего не удаляется. Если домен или подсеть пропали из источника, в списке они остаются.

Почему накопительно: исчезновение записи из конкретного источника не означает, что блокировку сняли. Источники неполны, ведутся разными командами, периодически теряют записи и меняют охват. Накопление даёт полноту — ценой того, что часть записей со временем может устареть.

| Список | Источник | Сверка с источником | Публикация | Принцип |
|---|---|---|---|---|
| `Telegram/telegram-ipv4.txt`, `Telegram/telegram-ipv6.txt` | сети Telegram + CDN с медиа | каждые 12 часов | только при изменении данных | зеркало |
| `blocked/rkn-domain.txt`, `blocked/rkn-with-wildcard.txt` | четыре проекта (таблица «Источники доменов» выше) | Noktomezo — каждые 12 часов, полное слияние всех четырёх — еженедельно | еженедельно, пятница 08:00 UTC | накопитель |
| `blocked/ipv4.txt` | Noktomezo, `ipsets/full.lst` | каждые 12 часов | еженедельно, пятница 08:00 UTC | накопитель |
| `blocked/ipv6.txt` | [bol-van/rulist](https://github.com/bol-van/rulist), `reestr_smart6.txt` | еженедельно | еженедельно, пятница 08:00 UTC | накопитель |
| [`corp/`](corp/README.md) | см. [corp/README.md](corp/README.md) | еженедельно | еженедельно, пятница 08:00 UTC | накопитель |

Всё обновляется автоматически по расписанию, без ручного вмешательства. Точное время последнего изменения каждого файла — в таблице статуса выше.

**Защита от порчи списка.** Каждая загрузка проверяется на правдоподобность размера. Если источник временно отдал пустой или подозрительно короткий ответ, обновление пропускается и остаётся предыдущая версия файла — лучше слегка устаревший рабочий список, чем затёртый неполными данными.

Расписание `corp/` подробно — в [corp/README.md](corp/README.md).

## Формат

**Домены** — обычный текст, один домен на строку, без комментариев. В `rkn-with-wildcard.txt` часть строк начинается с `*.`.

```
example.com
*.another-domain.ru
```

**IP (`blocked/ipv4.txt`, `blocked/ipv6.txt`)** — CIDR-нотация, один диапазон на строку, без комментариев. IPv4 и IPv6 — в отдельных файлах.

**IP (`Telegram/`)** — та же CIDR-нотация, плюс шапка из строк, начинающихся с `#`: источник, дата последнего изменения и число диапазонов. Инструменты, пропускающие строки с `#` (это делает большинство), читают файл без каких-либо изменений в настройке.

```
91.108.56.0/22
2001:b28:f23d::/48
```

## Использование

**AdGuard Home / Pi-hole** — добавь как источник кастомного блок-листа:
```
https://raw.githubusercontent.com/AbbeyLubber/ru-blocklist-aggregator/main/blocked/rkn-with-wildcard.txt
```

**hosts-файл** — используй `blocked/rkn-domain.txt`, добавь `0.0.0.0` или `127.0.0.1` перед каждой строкой.

**Xray / sing-box / v2ray** — `blocked/rkn-with-wildcard.txt` как источник доменного правила маршрутизации, `Telegram/telegram-ipv4.txt` / `Telegram/telegram-ipv6.txt` — отдельным IP-правилом (например, чтобы направлять трафик Telegram напрямую, минуя прокси).

**MikroTik (RouterOS v7)** — DNS-based address-list из `blocked/rkn-domain.txt`; поддомены — через `match-subdomain=yes` в правиле, без wildcard в самой строке.

## Дисклеймер

Этот репозиторий агрегирует уже общедоступные данные из открытых источников в информационных и исследовательских целях. Здесь нет инструментов обхода блокировок, прокси или VPN — только справочные списки доменов и IP-адресов.

Проект не аффилирован ни с одним из перечисленных источников и не может гарантировать точность, полноту или актуальность их данных. Материалы предоставляются «как есть», без каких-либо гарантий, явных или подразумеваемых.

Как и в каких целях использовать эти списки — решение и ответственность самого пользователя, включая соблюдение законодательства своей юрисдикции.
